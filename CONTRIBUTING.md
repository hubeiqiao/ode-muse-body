# Contributing to Ode

Help give Muse a reliable body. Start with a small issue or a focused change, describe the actual user behavior, and include reproducible offline verification.

Read [AGENTS.md](AGENTS.md), [architecture](docs/ARCHITECTURE.md) and [safety](docs/SAFETY.md). Keep the original MIT attribution. Use synthetic fixtures; never submit API keys, account handles, board identities, calibration, personal screenshots, task receipts or conversation history.

Install the development dependencies and run the Python and Node commands in [TESTING.md](docs/TESTING.md). Rebuild the companion when changing its source, and include its distributable and third-party notices. Avoid device/model calls in tests. Report physical acceptance separately from offline checks.

For security issues, share a minimal synthetic reproducer with the repository owner privately. Do not post credentials or private device frames in public issues. No device access or publishing is authorized by a contribution.
